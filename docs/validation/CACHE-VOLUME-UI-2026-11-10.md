# Native sample UI: cache and volume increment

The new samples bundle was opened with a generated internal temporary workspace. It did not use personal files, real shell integration, Xcode preferences, login items, notifications or physical eject. The installed normal build8 was not replaced. This is developer observation, not human/VoiceOver/beta acceptance.

At the 1050×690 minimum content size, both Portuguese and English were observed:

- Choose volume and scan the entire generated volume; hidden entries appear. The source volume remains separate from the selected cache SSD and scan-data storage option.
- Expand a directory, select its child and see the containing map block highlighted with an explicit containment caption. Keyboard Delete opens review; search finds a nested file across the volume. Tree headers update when language changes.
- Review real physical item spelling and volume, cancel without mutation, confirm fixture Trash and observe refreshed buckets. Moving within the same volume into Trash does not claim freed space.
- Show no transferred caches before the first selection, analyze all eligible entries, keep exceptions visible, review one batch and transfer generated data only. Configured and verified states differ; source retention is stated. Explicit simulated evidence is confined to the clearly marked sample context and cannot qualify a production provider.
- Verify and finish the sample transfer, disconnect/reconnect only its generated SSD directory, observe temporary network/memory mode, historical verification date and pending reopening. Restore the generated graphical cache through its own review. Controls and review sheets remain reachable at minimum size.

The observation found three routine corrections: refresh after cache mutation should keep the cache result page visible; three sample-only descriptions needed English translations; table spacing should keep the percentage column inside the minimum viewport. An obsolete tracking hint was also corrected. These fixes have their own code/test review and will receive a short final-package recheck. The final source includes a regression for cache transfer while a previous explorer snapshot is refreshed.
